數據庫規範化

Database Normalization

1NF → 2NF → 3NF 互動學習

📚 情境題

小健係一所學校嘅數據庫管理員，要處理學會主席嘅資料。

📌 規則

  • 每一個學會由 一位主席 帶領
  • 每名學生最多只可帶領 一個學會

📋 表格 CLUB 結構

CLUB (ClubID, ClubName, Chairperson, SID, Class)
欄位意思
ClubID學會編號（主鍵）
ClubName學會名稱
Chairperson主席姓名
SID主席嘅學生編號
Class主席嘅班別

👀 睇下實際資料

假設表格入面有以下資料：

ClubIDClubNameChairpersonSIDClass
C01圍棋學會阿明S1015A
C02數學學會阿MayS2055B
C03音樂學會阿KenS3124C
C04辯論學會阿MayS2055B

🤔 發現問題！ 阿May (S205) 同時係兩個學會嘅主席？

違反規則「每名學生最多只可帶領一個學會」 → 即係 SID 應該都可以 uniquely identify 一行！

🔗 功能依賴 (Functional Dependencies)

由規則可以推斷出兩條重要嘅 functional dependency：

① ClubID 決定一切

ClubID → ClubName, Chairperson, SID, Class

因為「每個學會只有一位主席」

② SID 都可以決定一切

SID → Chairperson, Class, ClubID, ClubName

因為「每名學生最多只可帶領一個學會」

✅ 主鍵 (Primary Key) = ClubID

✅ SID 係另一個 candidate key（候選鍵）

🎯 三大範式口訣

"The key, the whole key, and nothing but the key"

「主鍵、完整主鍵、只有主鍵」

1NF

The KEY

每格只可以放 一個原子值（atomic value），唔可以重複群組。

2NF

The WHOLE Key

非主鍵屬性必須依賴 完整嘅主鍵，唔可以只依賴部分（part of key）。

3NF

NOTHING but the Key

非主鍵屬性必須 直接 依賴主鍵，唔可以經第三者（傳遞依賴）。

✅ (i) 符合 1NF 嗎？

1NF 要求：

每個欄位只可以放 單一原子值（不可分割）

❌ 違反 1NF

ClubIDMembers
C01阿明, 阿仁, 阿May

一格放多個值 ❌

✅ 我哋嘅 CLUB

ClubIDChairperson
C01阿明

每格一個值 ✅

📝 答案

符合 1NF。因為 CLUB 表格中每個欄位都只儲存單一原子值，沒有重複群組。

✅ (ii) 符合 2NF 嗎？

2NF 要求：

① 已符合 1NF
② 沒有 部分依賴（partial dependency）

🤔 咩叫 partial dependency？

當 主鍵由多個欄位組成（複合主鍵）時，如果某個非主鍵屬性 只依賴其中一部分，就係 partial dependency。

例子（其他 case）：

主鍵 = (StudentID + CourseID)

StudentID → StudentName
↑ StudentName 只依賴 StudentID 嘅一部分 = partial dependency ❌

📝 答案：CLUB 符合 2NF

因為 CLUB 嘅主鍵 ClubID 係 單一欄位（唔係複合主鍵），所以根本冇可能有 partial dependency，自動符合 2NF ✅

❌ (iii) 點解唔符合 3NF？

3NF 要求：

非主鍵屬性必須 直接 依賴主鍵，
不能經第三者（即係冇 transitive dependency 傳遞依賴）

🔍 我哋睇下 CLUB 嘅依賴關係：

ClubID → SID → Chairperson, Class

↑ Chairperson 同 Class 唔係直接依賴 ClubID，而係經 SID 轉一個彎！

🚨 傳遞依賴 (Transitive Dependency)

ClubID → SID，而 SID → Chairperson, Class

結果：ClubID → Chairperson, Class 係透過 SID 間接傳過去，違反 3NF。

😱 點解傳遞依賴會出問題？

睇下如果保持原本嘅 CLUB 表格，會有咩問題：

ClubIDClubNameChairpersonSIDClass
C01圍棋學會阿明S1015A
C02數學學會阿明S1015A
C03音樂學會阿明S1015A

🔴 1. 資料重複 (Redundancy)

阿明同 S101、5A 重複出現多次

🔴 2. 更新異常 (Update Anomaly)

如果阿明升班，要逐行修改！漏改一行就資料不一致 😱

🔴 3. 刪除異常 (Delete Anomaly)

如果刪走某個學會，可能會連 student 資料都刪埋！

💡 (iv) 規範化到 3NF

解決方法：將 CLUB 拆成兩個表，把傳遞依賴拆走！

📋 表 1: CLUB

CLUB (ClubID, ClubName, SID*)

* SID 係 foreign key，連接到 STUDENT 表

ClubIDClubNameSID
C01圍棋學會S101
C02數學學會S205

📋 表 2: STUDENT

STUDENT (SID, Chairperson, Class)
SIDChairpersonClass
S101阿明5A
S205阿May5B

✅ 而家 Chairperson 同 Class 直接依賴 SID（喺 STUDENT 表），冇傳遞依賴！
